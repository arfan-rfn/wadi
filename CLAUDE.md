It began as an audit answering "what is extraction still missing?" and the answer was mostly *not what it looked like*: endpoint extraction was already 365/365 (the one "missing" controller is wholly commented out), and an independent DI-aware reachability oracle agreed with wadi on 365 of 382 call sites with **zero over-reports** — the corpus, not the extractor, accounted for the bulk of what read as missing. What was real: **response payloads** (every endpoint published `{status, msg, data}` with `data` an unbound `T`; no signature carries the type because services declare a RAW `Response`, so it is read from the producer's return statement — 0 → 213 of 291 answered, plus `always-null` as its own terminal for a field every construction sets to null); **declared HTTP statuses** (365/365, marked `builder`/`explicit`/`annotation`/`default`, named `declared_` because a 500 from an exception or a 403 from the security layer is in no handler source); **CORS/CSRF/entry-point** finally consumed (the pack had emitted them since export 2.8.0 into a model no service read); **token propagation** (`forwarded`/`not-forwarded`/`undetermined`, was null on 382/382, the negative claimed only where provable); **reachability provenance**; and **`unexercised_vocabulary`** so a zero says whether it was measured or never exercised. Triggered by a system whose policy wadi could not read a word of: ICPC (804 endpoints, 118 controllers) declares its authorization in eight annotations of its own invention, held in a sibling Maven artifact and enforced by AspectJ advice that *votes* on a request-scoped bean rather than throwing — so 637 endpoints published `roles: []` with nothing beside it. Three independent causes, each sufficient: the annotation pass matched a closed list of eight Spring names; `gates()` wanted a rejection marker or one of thirteen call names and scored **0/8** against the real authorizers; and a library compiled *into* a service was modelled as a peer service, putting the binding in another CPG. The fix is a change of question — **a security annotation is not a name on a list, it is an annotation whose consumer can deny the request**, which is a graph property: read the binding (advice parameter type, `@annotation(...)` designator, `getMethodAnnotation` read), gate on whether the construct touches caller **identity** (8/8 on the real authorizers where deny-shape scored 1/8, and 0/4 on train-ticket's tracing advice), and scope to exactly the annotated methods. §5.2.12 adds `AuthEffect.REQUIRE_RELATIONSHIP` + `AuthRelationship` because 85% of that system's policy is a *relation to a resource* ("manage **this** contest"), not a role — the commonest authorization model there is, and one the vocabulary previously had no word for. §5.2.13 then fixed the mirror-image matcher defect it surfaced: a path template absorbing a literal let nine endpoints inherit a `permitAll` written for a sibling and publish as **evidenced-public** when they require authentication. **Measured end to end: 562 endpoints gain a read policy, `withheld` 7 → 0, 14 permissions across 282 endpoints, 9 endpoints corrected from public to protected with 0 regressions**; verified against the ICPC source by an independent comment-stripped oracle at 804/804 handlers and 14/14 permissions — an oracle whose own first run produced two phantom "extraction defects" that both dissolved on inspection. The standing lesson generalizes §5.2.11's: **a delta is a hypothesis until one of its members is opened, in both directions.** **Phase 2.9.4 — A library is not a service (§5.2.14) — is complete (ships as 0.8.1).** §5.2.6 already classified in-repo library modules and staged their sources into each dependent's parse; ICPC defeated it twice. Dependency resolution ran **per repository** while the answer needs the whole system, so `<dependency>` on a module in a *sibling repo* — the ordinary shape for a shared internal jar — resolved against a map that could never contain it. And a module carrying a `@RestController` was read as deployable, which a library shipping a reusable web fragment is not; the proof is that the consuming app's own `SecurityConfig` carries the rule for that route. Modules are now pooled across every repo of a system before classification, deployability is marked by an entry point or war packaging rather than web presence, and `library_roots` gained a `repo::root` qualifier so the stage can reach a sibling checkout. **The payoff is mostly not auth: 335 of 336 unresolved response shapes were types the library declares.** Measured end to end: response shapes resolved **468 → 803**, relationship-scoped endpoints **562 → 643**, relation vocabulary **7 → 8** (which also settles §5.2.12's open `@Admin` hypothesis). A source union is the sum of its parts, so the analyzer container is sized 10g — **a wadi stack now wants ~10 GB available to Docker.** Open items are tracked in `TODOS.md`, not prose. **Phase 3 (async + security analysis) follows** per §11 — it consumes this model, so it is sequenced after. Wadi is a polyglot microservice static-analysis platform built on Joern: it analyzes an entire microservice system (one repo or many), extracts per-endpoint interprocedural control-flow graphs, detects cross-service communication, stitches flows across services (with confidence tiers, Neo4j graph, and a coverage report), and exposes the result via a REST API, MCP server, and web frontend. ## Commands

- `make sync` — install the uv workspace. `make test` — full Python suite (Mongo integration tests spin up a Docker container; they skip without Docker). `make test-unit` — no infrastructure.
- `make lint` / `make fmt` / `make typecheck` — ruff + pyright strict, workspace-wide, zero-tolerance in CI.
- `make schema` — regenerate `schemas/` + frontend TS types after ANY `wadi-contracts` change; CI fails on staleness. Same for `make sync-compose` after editing `infra/docker-compose.yml` (the CLI embeds a copy).
- `cd joern-platform && sbt test` — Scala conformance tests (build real CPGs from `fixtures/`); also writes `target/petstore-export/export.json`, which the Python cross-language golden test consumes (`pytest services/extraction-worker/tests/test_real_export.py`).
- `make joern-image` then `make e2e` — the whole-stack conformance e2e (real Joern container).
- Run a single Python test: `uv run pytest path/to/test_file.py::TestClass::test_name`.

## Rules That Govern All Future Work

These come from `architecture.md` and are binding, not aspirational:

- **Decisions are recorded before they're implemented.** Any structural change updates `architecture.md` first, in its format: decision + rationale + rejected alternatives. Docs move with code in the same PR.
- **P1 — Coupling only through contracts.** Services never import each other; all inter-service communication is versioned JSON artifacts in MongoDB + the job collection. Shared code lives in `libs/*` only.
- **P4 — Single writer per data domain.** Each Mongo collection / data domain has exactly one writing service. To cause a write in another domain, call that domain's owner (usually the orchestrator's REST API).
- **P5 — Joern is stock and pinned, never forked.** All customization via CpgPass / CPGQL query packs / tags compiled into a jar in the `wadi-joern` image. CPGs are evictable cache, never a store.
- **P6 — Extension decision rule.** Needs to see inside one service's code graph → Scala (pass or query pack in `joern-platform`). Spans services, configs, or extracted artifacts → Python (service or library).
- **P7 — Symbolic truth, LLM judgment.** The core pipeline is deterministic and runs with no API keys. LLM output is always provenance-marked (`llm-guessed`), never blended into ground truth.
- **P8 — Every framework pack ships a conformance fixture** (tiny sample repo + expected JSON, diffed in CI).
- **P10 — Honest unknowns.** What analysis cannot determine is materialized explicitly (placeholder nodes, "target undetermined" facts), never omitted or falsely resolved.
- **Identity stability:** service/endpoint IDs are deterministic and content-derived (hash of service + method + normalized URI), never random per run.
- **Contracts are the spine:** Pydantic v2 models in `libs/wadi-contracts` are the single source of truth; frontend TS types are generated from their JSON Schema, never hand-written. Every artifact carries `schema_version`, snapshot key, and tz-aware UTC timestamps. The tag vocabulary (`endpoint=…`, `sink=…`, `model=…`) is a versioned registry in `wadi-contracts`, not a pack convention.

## Planned Structure & Toolchain

Monorepo (see `architecture.md` §9 for the full tree): `joern-platform/` (Scala/sbt — the only JVM code), `libs/` (shared Python packages: wadi-contracts, wadi-storage, wadi-config, wadi-repo, wadi-joern-client), `services/` (orchestrator, extraction-worker, stitcher, mcp-server — FastAPI/worker apps), `cli/` (Typer + httpx; compose-wrapper + REST client only, no DB access), `frontend/` (Next.js App Router + generated types), `infra/` (docker-compose).

- **Python 3.12+, uv workspace, FastAPI, Pydantic v2; pyright strict + ruff + pytest** (CI-enforced).
- **Scala:** scalafmt + warnings-as-errors; packs stay declarative (a pack needing hundreds of lines is a design smell).
- **Storage:** MongoDB (Tier 1, source of truth) → Neo4j (Tier 2, derived/rebuildable); CPG files are Tier 0 cache. Only `wadi-storage` imports DB drivers; only `wadi-config` reads env vars (`WADI_*` prefix).
- Planned Makefile targets: `make up / test / schema / slice`. `make schema` regenerates frontend types; CI fails if they're stale.
- Default ports: orchestrator API 9234, frontend 9235 (the "WADI keypad block"); DB ports never published to the host.
