  **Shapes**
  - **S1 marker on handler or class:** Spring method security, Jakarta, Quarkus, Micronaut, ASP.NET, NestJS, Django/DRF, Flask.
  - **S2 rule table matched by path:** Spring `authorizeHttpRequests`, Quarkus permissions, Micronaut `intercept-url-map`, servlet `web.xml`.
  - **S3 chain in registration order, scoped by group, plugin or inheritance:** Express, Fastify, gin, echo, chi, Django middleware, Rails callbacks.
  - **S4 injected dependency:** FastAPI.
  - **S5 policy object found by name or convention, often called imperatively:** Pundit, CanCanCan, ASP.NET handlers, NestJS policies, DRF object permissions.

  ## Part 3. Tokens and claims
  
  Status: [RFC 9068](https://www.rfc-editor.org/info/rfc9068), [RFC 8693](https://www.rfc-editor.org/info/rfc8693) and [RFC 8707](https://www.rfc-editor.org/info/rfc8707) are Proposed Standards (October 2021, January 2020, February 2020). The security BCP is [RFC 9700](https://www.rfc-editor.org/info/rfc9700), BCP 240, January 2025.
  
  | Check | What the standard says | Where configured |
  |---|---|---|
  | Signature, issuer | 9068 §4: validate signature, reject `alg: none`, `iss` must match exactly, `typ` must be `at+jwt` | Spring `issuer-uri`, `jwk-set-uri`; ASP.NET `Authority`; Micronaut `token.jwt.signatures.jwks` |
  | Audience | 9068 §4: reject unless `aud` contains this server; §3: `aud` mirrors the 8707 `resource` parameter. 9700 §2.3: tokens SHOULD be audience-restricted | Spring `audiences`, not validated by default; ASP.NET `Audience`; fastify `allowedAud` |
  | Expiry | 9068 §4: now before `exp` | Spring default validator, 60 s skew |
  | Scopes | 9068 §2.2.3 `scope` claim; the check is "beyond the scope of this profile". 8707 §2.2: downscoping | Spring `SCOPE_` authorities in rules; FastAPI `Security(scopes=)` plus your code |
  | Roles, groups | 9068 §2.2.3.1: `roles`, `groups`, `entitlements`, no fixed vocabulary | Spring `JwtGrantedAuthoritiesConverter`; elsewhere custom |
  | Tenant | No standard claim. 8693 §4.1: only top-level claims and the current `act` actor count | Custom validator code |
  
  ## Implications for a rules-as-data design
  
  **A data rule can capture**
  - S1 markers: name, the argument carrying a role or policy name, class-versus-method override, the opt-out marker.
  - S2 tables with literal entries; precedence declared per rule set (first match, longest path, ordered chain), not one built-in algorithm.
  - The default: one fact per framework plus the switches that flip it.
  - Config-file authentication: issuer, audience, key source.
  - Externalized call sites: callee name and argument positions of action and resource.
  
  **Needs code**
  - Scope of an S3 chain (registration order, nesting, inheritance) and S4 dependency graphs.
  - Rule tables built with constants, lambdas or custom matchers.
  - Resolving a policy name, guard or dependency to the deciding body; convention lookups (Pundit).
  - Expression languages (SpEL, CEL).
  
  **Not readable from a repository**
  - Casbin database policy, Keycloak server policy, OpenFGA and SpiceDB tuples, Verified Permissions stores, Oso Cloud, OPA bundles built elsewhere.
  - Token contents and identity-provider role mappings.
  
  Publish these as explicit unknowns, with the call site as evidence.
