## Affected Pages/Routes
- `/s/{snapshotId}/e/{endpointId}?pane=data`: the Data list in the workspace's left pane: six states, entity selection, call-site highlight.
- `/s/{snapshotId}?view=data`: the entity by operation matrix: columns, cell drill-in, notes with unresolved counts.
- `GET /api/v1/snapshots/{id}/entities`: the reverse view, on a fresh snapshot and on one analyzed before the phase.
- `GET` endpoint list and detail routes: the `entity_access` summary on each row, payload and latency before and after.
- MCP `endpoint_detail`, `endpoint_icfg`, `entity_usage`: each called through the MCP server itself.

## Key Interactions to Verify
- Switch Calls to Data and back on the workspace; reload the URL and land on the same pane and entity.
- Select an entity in the Data list; its repository call sites highlight on the flow canvas and the source pane follows.
- Click a matrix cell; the endpoints that may perform that operation are listed and each opens its workspace.
- Open an endpoint that only forwards to another service; the Data list names the outbound call.

## Edge Cases
- A snapshot analyzed before the phase shows "predates entity facts" in the Data list, `/entities` and `entity_usage`, never "no repository call found".
  Value: protects=None is distinct from an empty list on every reader; fails_when=a reader treats a missing summary as empty; why_new=no entity fact exists today; seam=none; no_claim=none beyond protects
- A save that cannot be split shows one "create or update" chip and is counted in its own matrix column.
  Value: protects=create-or-update never merges into create or update; fails_when=a fold unions it into both verbs; why_new=new operation value; seam=none; no_claim=says nothing about whether the split rules are right
- A repository `default` method named like a finder publishes `unknown`.
  Value: protects=hand-written repository bodies are not classified by name; fails_when=the name table is applied to a project-implemented method; why_new=new classifier; seam=none; no_claim=does not analyze the body
- A query that deletes one entity and reads another yields two accesses with two operations.
  Value: protects=one access per entity per query; fails_when=the leading verb is applied to every entity; why_new=new query reader; seam=none; no_claim=keyword-level reader, not a SQL parser
- A failed fetch of entity access shows an error with retry and no claim.
  Value: protects=a fetch error never renders as a finding; fails_when=the error path falls through to an empty state; why_new=new pane; seam=none; no_claim=none beyond protects
- A statement with two repository calls shows two sites.
  Value: protects=the accounting unit is the call site; fails_when=only the primary call of a statement is kept; why_new=new node field; seam=none; no_claim=none beyond protects

## Critical Paths
- Fixture `spring-data-crud-matrix` through the real Joern container to the REST and MCP readers (`make e2e`).
  Value: protects=export 2.14.0 raw facts reach every reader intact; fails_when=Scala and Python disagree on the `db` row shape; why_new=new export fields; seam=none; no_claim=fixture only, not a real corpus
- The nine existing fixtures keep the same set of db-tagged call ids after repository detection becomes transitive.
  Value: protects=existing sink tagging; fails_when=the transitive check tags or drops a call on a fixture without a base interface; why_new=detection rule changes; seam=none; no_claim=says nothing about ICPC, which is measured separately
- The repository call-site oracle, reading comment-stripped train-ticket source, reconciles with wadi site by site.
  Value: protects=completeness of the accounting; fails_when=the exporter omits a call site; why_new=no source oracle is committed today; seam=none; no_claim=regex over source, so each disagreement is opened by hand
- A gate flag that is on for a rules version other than the current one fails the build.
  Value: protects=single verbs are published only on a current score; fails_when=a rule is edited and the flag is left on; why_new=new gate; seam=none; no_claim=does not prove the score itself is right
